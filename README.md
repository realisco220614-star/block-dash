# 블록 대시 레이스

우리 반 전체가 태블릿으로 같은 방에 들어와 하늘 코스를 3바퀴 달리는 실시간 달리기 게임.

- `public/index.html` — 게임 전체 (HTML 한 파일 + Three.js r128, 빌드 없음)
- `public/three.min.js` — cdnjs가 막힌 곳에서 대신 쓰는 Three.js 사본
- `database.rules.json` — Realtime Database 보안 규칙
- `firebase.json` — Hosting·Database 배포 설정
- `block-dash-prototype.html`, `밀키트.md`, `밀키트-2차.md` — 처음 받은 1인용 프로토타입과 설계도

## 명령어 없이 올리기 (브라우저 클릭만, 약 15분)

명령어 창이 어렵다면 이 방법을 쓴다. 실시간 연결은 Firebase, 게임 화면은 GitHub Pages에 둔다.

**A. Firebase 콘솔에서 (실시간 연결 준비)**
1. https://console.firebase.google.com → **프로젝트 추가** → 이름 입력(예: `blockdash-5-1`) → Google 애널리틱스는 꺼도 된다 → **프로젝트 만들기**.
2. 왼쪽 메뉴 **빌드 → Authentication → 시작하기** → **로그인 방법** 탭 → **익명** → 사용 설정 → 저장.
3. 왼쪽 메뉴 **빌드 → Realtime Database → 데이터베이스 만들기** → 위치는 가까운 곳(싱가포르) → **잠금 모드로 시작** → 사용 설정.
4. Realtime Database 화면의 **규칙** 탭 → 안에 있는 글을 모두 지우고 `database.rules.json` 파일 내용을 그대로 붙여 넣기 → **게시**.
5. 왼쪽 위 톱니바퀴 → **프로젝트 설정** → 아래쪽 **내 앱** → 웹 아이콘(`</>`) → 앱 이름 입력 → **앱 등록**. 화면에 나오는 `firebaseConfig = { ... }` 부분을 복사한다. (3번을 먼저 해야 이 안에 `databaseURL`이 들어 있다.)
6. 복사한 값을 `public/index.html` 맨 위 `FIREBASE_CONFIG` 자리에 붙여 넣는다. 이 값은 비밀번호가 아니라 프로젝트 이름표라서 공개돼도 괜찮다(보안은 4번의 규칙이 맡는다).

**B. GitHub에서 (게임 화면 올리기)**
1. github.com 로그인 → 오른쪽 위 **+ → New repository** → 이름 `block-dash` → **Public** → Create repository.
2. 화면의 **uploading an existing file** → `public` 폴더 안의 `index.html`, `three.min.js` 두 파일을 끌어다 놓기 → **Commit changes**.
3. 저장소의 **Settings → Pages** → Branch를 `main`, 폴더 `/(root)`로 두고 **Save**. 1~2분 뒤 `https://아이디.github.io/block-dash/` 주소가 생긴다.
4. 다시 Firebase 콘솔 → **Authentication → 설정 → 승인된 도메인 → 도메인 추가** → `아이디.github.io` 입력.
5. 태블릿 2대로 그 주소에 들어가 방 만들기·입장이 되는지 확인한다.

게임을 고친 뒤에는 B-2처럼 `index.html`을 다시 올리면 된다(같은 이름이면 덮어쓴다). 규칙이 바뀌었을 때만 A-4를 다시 한다.

## 처음 한 번: Firebase 연결 (명령어 사용, 약 10분)

1. <https://console.firebase.google.com> 에서 프로젝트를 만든다. (요금제는 무료 Spark 그대로)
2. **빌드 > Authentication > 시작하기 > 로그인 방법 > 익명** 을 켠다.
3. **빌드 > Realtime Database > 데이터베이스 만들기** (위치는 아무 곳, "잠금 모드"로 시작).
4. **프로젝트 설정 > 내 앱 > 웹 앱(</>) 추가** 로 웹 앱을 하나 등록한다. (Hosting이 설정값을 자동으로 넘겨주려면 필요)
5. 컴퓨터에서:

```bash
npm install -g firebase-tools
```

```bash
firebase login
```

```bash
firebase use --add
```

```bash
firebase deploy
```

`firebase deploy` 한 번으로 게임(Hosting)과 보안 규칙(Database)이 함께 올라간다.
게임을 고칠 때마다 다시 `firebase deploy`를 해야 하고, 보안 규칙(`database.rules.json`)도 게임과 짝이 맞아야 한다.
끝나면 나오는 `https://프로젝트이름.web.app` 주소가 학생들이 들어올 주소다.

> Firebase Hosting에 올리면 `index.html` 맨 위 `FIREBASE_CONFIG`는 **비워 둬도** 된다. 자동으로 연결된다.

## 학교 와이파이에서 web.app이 안 열릴 때 (GitHub Pages)

1. Firebase 콘솔 > 프로젝트 설정 > 내 앱 > `firebaseConfig` 값을 복사해 `public/index.html` 위쪽 `FIREBASE_CONFIG`에 붙여 넣는다. (`databaseURL` 포함)
2. `public` 폴더 내용을 GitHub 저장소에 올리고 Pages를 켠다.
3. Firebase 콘솔 > Authentication > 설정 > **승인된 도메인**에 `아이디.github.io`를 추가한다.

주소(페이지)만 옮겨지는 것이고 실시간 연결은 계속 Firebase(`*.firebasedatabase.app` / `*.firebaseio.com`)를 쓴다.
이 주소 자체가 학교망에서 막혀 있으면 방 만들기·입장이 "인터넷 연결을 확인해 주세요"로 실패한다. **혼자 연습**은 그래도 된다.

## 수업에서 쓰는 법

- **선생님** (교실 TV에 연결한 기기): 주소 접속 → `선생님: 방 만들기` → 화면에 뜬 4자리 코드를 알려 준다 → 이름이 다 뜨면 `시작`.
  경기 중에는 코스 전체와 실시간 순위가 나온다. 끝나면 `한 판 더`.
- **학생**: 주소 접속 → 이름·색 정하기 → `방 들어가기` → 코드 누르기 → 기다리기.
- 한 방 최대 20명. 경기 도중에 들어오거나 새로고침한 학생은 구경하다가 다음 판부터 달린다.
- 선생님 기기를 새로고침했다면 다시 `방 만들기`를 누르면 같은 방으로 돌아간다.
- 대기 화면에서 **개인전/팀전**, 팀 수(2팀·3팀), 팀 나누기 방법을 고른다.
- 인원이 적으면 **🤖 컴퓨터 친구**를 −/＋ 버튼이나 "20명까지 채우기"로 더한다. 컴퓨터 친구는 선생님 기기(교실 TV)가 대신 달리고, 학생 화면에는 다른 친구처럼 보인다. 서로 부딪히고 아이템·능력도 주고받는다. 팀전에서는 출발할 때 인원이 적은 팀에 들어간다. 그래서 경기 중에는 선생님 기기를 끄거나 새로고침하지 않는다. 팀전에서는 학생 이름을 누르면 다른 팀으로 옮겨진다.
- 1등 도착 60초 뒤 또는 전원 도착 시 시상 장면(8초, 화면을 누르면 건너뜀) → 순위표. 기록은 저장되지 않는다.

## 조작

- 왼쪽 조이스틱 달리기 · ⬆ 점프 · 🎁 아이템 · ⭐ 능력 (키보드: 방향키/WASD · 스페이스 · E · Q)
- 스타트 부스터: 카운트다운 "출발!"이 뜨는 순간(앞뒤 약 0.3초)에 처음 앞으로 밀면 부스터. 미리 밀고 있으면 실패.
- 능력: 시작 화면(또는 대기 화면)에서 하나를 고른다. 출발 5초 뒤부터 쓸 수 있고, 쓰고 나면 쿨타임 동안 버튼에 남은 초가 보인다.

| 능력 | 하는 일 | 쿨타임 |
|---|---|---|
| 🏈 태클 | 앞 친구에게 몸을 날려 1.8초 동안 엎어지게 함 (닿는 거리가 넉넉함) | 4초 |
| 🌀 회오리 | 내 주변 4.6칸 친구들을 사방으로 멀리 날려 보냄 (가장자리면 떨어질 수 있음) | 7초 |
| 🔨 땅 쿵 | 땅에서는 제자리 쿵(3.8칸), 점프 중이면 내리찍어 넓게(5.6칸). 맞으면 바깥으로 튕기며 1.1초 멈칫 | 6초 |
| 🍯 끈끈이 | 뒤에 큰 꿀 웅덩이(5초 유지). 밟으면 1.8초 동안 아주 느려짐 | 6초 |

  방패는 한 번 막고, 거대화·리스폰 직후 깜빡임·같은 팀·이미 도착한 친구는 안 걸린다. 능력별 세기는 AI 18명 120판 시뮬레이션으로 맞췄다. 세기·범위는 `index.html`의 `ABP` 표 한곳에서 바꿀 수 있다.
- 물풍선 아이템은 빠졌다.
- 🦑 먹물 아이템: 내 앞에 있는(다른 팀) 친구들 중 **가까운 쪽 3분의 1**에게만 3초 동안 먹물이 덮인다(최소 1명, 최대 5명). 방패로 막을 수 있다.

## 학생들에게 공유하기

- 학생 주소는 배포 후 나오는 `https://프로젝트이름.web.app` 하나뿐이다. 방은 4자리 코드로 나뉘므로 여러 반이 같은 주소를 동시에 써도 섞이지 않는다.
- 주소 알려 주는 방법
  - 학급 게시판·클래스룸에 링크를 올리거나 칠판에 적는다.
  - QR 코드: 선생님 PC 크롬에서 주소를 연 뒤 주소창 오른쪽의 공유 아이콘 → "QR 코드 만들기". TV에 띄우면 학생들이 카메라로 찍어 들어온다.
  - 태블릿 홈 화면에 아이콘으로 두기: 크롬은 메뉴(⋮) → "홈 화면에 추가", 아이패드 사파리는 공유 → "홈 화면에 추가". 다음부터는 앱처럼 바로 열린다.
- 다른 선생님에게는 같은 주소를 알려 주기만 하면 된다. 다만 동시 접속 100명과 월 전송량을 같이 나눠 쓴다(아래). 따로 쓰고 싶으면 이 폴더를 받아 자기 Firebase 프로젝트로 배포하면 된다.

## 데이터베이스(Firebase Realtime Database) 운영

**무엇이 저장되나**: 방 상태, 학생 별명·캐릭터 색·세리머니·능력·팀, 경기 중 위치(초당 10번 덮어씀), 아이템·능력 알림. 실명·기록·순위는 남지 않는다.

**언제 지워지나**: 학생이 나가거나 연결이 끊기면 그 학생 항목은 바로 지워진다. 방은 선생님이 "방 닫기"를 누르면 지워지고, 안 닫아도 3시간이 지나면 다음에 누군가 방을 만들 때 정리된다.

**무료 요금제(Spark) 한도와 실제 사용량**

| 한도 | 이 게임 기준 |
|---|---|
| 동시 접속 100 | 한 방 최대 21(학생 20 + 선생님). 같은 시간에 4~5개 반까지 |
| 저장 1GB | 방 하나가 수십 KB라 걱정 없음 |
| 월 다운로드 10GB | 18명 한 판(대기 포함 약 2분 30초)에 약 60MB → **한 달 약 160판** (학교 20일 기준 하루 8판 정도) |

- 무료 요금제는 한도를 넘으면 그달 남은 기간 동안 연결이 막힐 뿐, **요금이 청구되지 않는다**. 결제 수단을 등록하지 않았다면 그렇다.
- 사용량은 Firebase 콘솔 → Realtime Database → **사용량** 탭에서 본다. 첫 주에 한 번 확인해서 하루 몇 판까지 괜찮은지 가늠하면 된다.
- 여러 반이 많이 쓰면 Blaze(종량제)로 바꾸면 된다. 초과분은 GB당 1달러 정도다. 바꿀 때는 콘솔의 "예산 알림"을 꼭 켠다.
- 위 숫자는 계산으로 낸 어림값이다. 실제는 콘솔 사용량이 정확하다.

**보안**: 익명 로그인한 기기만 읽고 쓸 수 있고, 학생은 자기 항목만, 방 설정·순위는 선생님 기기만 고칠 수 있다(`database.rules.json`). 규칙을 바꾸면 `firebase deploy`로 함께 올린다.

**게임을 고친 뒤**: `public/index.html`과 `database.rules.json`을 바꾸고 다시 `firebase deploy` 하면 된다. 학생 태블릿은 새로고침하면 새 버전을 받는다.

## 반 전체가 쓰기 전에 (태블릿 2대로 확인)

- [ ] 학교 와이파이에서 주소가 열린다.
- [ ] 한 대는 방 만들기, 다른 한 대는 코드로 입장이 된다.
- [ ] 시작을 누르면 카운트다운이 같이 나오고, 서로의 캐릭터가 보인다.
- [ ] 회전 막대가 두 화면에서 같은 각도로 돈다.

## 내 컴퓨터에서 시험하기 (에뮬레이터)

```bash
firebase emulators:start --project demo-blockdash
```

브라우저 탭 여러 개로 `http://127.0.0.1:5000/?emu=1` 을 연다. (`?emu=1`은 진짜 서버 대신 에뮬레이터에 붙으라는 뜻.
탭마다 다른 학생이 되려면 시크릿 창이나 다른 브라우저 프로필을 쓴다.)

## 데이터 구조

```
rooms/{코드}/meta            상태(lobby|count|result), 방장 ID, 만든 시각, 판 번호, 출발 시각, 출발 자리(slots)
                             mode(solo|team), teamCount(2~3), teamPick(auto|choose), teams(출발 때 확정한 팀),
                             bots(컴퓨터 친구 수), finalLapAt(마지막 바퀴 시작 시각), results(o 순위대로 ID, f 도착 시간·못 오면 -1)
rooms/{코드}/players/{id}    n 이름, c 색 4개, cheer 세리머니(0~3), ab 능력(0~3: 태클·회오리·땅 쿵·끈끈이), team 팀(0~2), j 들어온 시각,
                             s 위치·상태 배열(초당 10회), fin 도착 시간
rooms/{코드}/bots/{bot1~}   컴퓨터 친구 (선생님 기기만 씀): n 이름, c 색, ab 능력, cheer, s 위치 배열, fin
rooms/{코드}/events          b/bg 바나나 설치·제거, w/wp 물풍선 발사·명중, x 아이템 상자, i 먹물(맞는 친구마다 한 건), l 추격 번개,
                             k 태클, wh 회오리, pd 땅 쿵, hy 끈끈이 (맞은 쪽 기기가 거리 확인 후 적용)
roomIndex/{코드}             방 만든 시각 (3시간 지난 방 정리용)
clock/{id}                   서버 시계 맞추기용 임시 값
```

`s` 배열: `[시각ms, x, z, 높이, 방향, 속도, 랩, 코스위치, 상태비트]`
(상태비트: 1 빙글빙글 · 2 방패 · 4 부스터 · 8 무적 · 16 땅 · 32 떨어지는 중 · 64 거대화 · 128 먹물 · 256 번개 맞음 · 512 능력 쓰는 중 · 1024 태클 맞고 엎어짐 · 2048 느려짐(꿀))
